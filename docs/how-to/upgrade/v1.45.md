# Upgrading to v1.45

**Breaking.** Secrets are referenced by NAME and resolved through one declared
source; the `…Env` spellings are gone and the library chart delivers secrets as
files. Allowed in a minor for a product that declares itself `stabilizing`
([release.md §2](../../contracts/release.md)); the reasons are in
[config.md §5](../../contracts/config.md) and decision
[0012](../../decisions/0012-stabilization-amendments.md).

## What changed

| Before (v1.44) | Now (v1.45) |
|---|---|
| `database.passwordEnv: DB_PASSWORD` | `database.passwordSecret: db/password` |
| `bucket.credentialsEnv: {accessKeyID: A, secretAccessKey: B}` | `bucket.credentialsSecret: {accessKeyID: s3/accessKeyID, secretAccessKey: s3/secretAccessKey}` |
| no `secrets` block (the environment) | `secrets: {source: file, root: /var/run/secrets/<app>}` (shared fragment `schemas/fragments/secrets.json`) |
| chart `platform.secrets: {VAR: {secretName, key}}` renders `valueFrom.secretKeyRef` | chart `platform.secretFiles: {<name>: {secretName, key}}` renders one projected volume, mode 0440, mounted at `config.secrets.root` |
| `config.Secret(envName)` | `config.NewSecrets(src).Get(ctx, field, name)` |
| `conformance.EnvIsDeclared(t, out, dep, secrets, allowed...)` | `conformance.EnvIsDeclared(t, out, dep, allowed...)`, plus `SecretsAreFiles` and `NoEnvSecretFields` |

Kept: `platform.config.pathEnv`. It names the variable that carries the path of
the configuration file ([service.md §1](../../contracts/service.md)). It is not a
secret, and the file it points at is not what the service reads it from.

## Steps

1. **Bump the pin** to v1.45.0 (the Go module, the chart dependency, the Python
   and TypeScript packages).
2. **Rename each field in the service's schema and file.** A name is a relative
   path of letters, digits, `.`, `_`, `-`, with `/` between segments; it never
   starts with `/` and never has an empty, `.` or `..` segment. Add the
   `secrets` property to the service's schema, `$ref`ing
   `schemas/fragments/secrets.json`.
3. **In the service**, read each name through the one resolver:

   ```go
   src := cfg.Secrets // config.SecretsSource
   r, err := config.NewSecrets(src /*, config.WithStore("ssm", yourSSMStore) */)
   password, err := r.Get(ctx, "database.passwordSecret", cfg.Database.PasswordSecret)
   ```

   `env` is allowed off Lambda (the name is the variable) and is refused on a
   function (`AWS_LAMBDA_FUNCTION_NAME` set); `ssm` and `openbao` read through a
   `config.Store` you supply, so this package links neither client. Roots are
   checked: `file` and `ssm` need an absolute root, `openbao` a mount, none may
   have an empty, `.` or `..` segment.
4. **In the chart**, replace `platform.secrets` with `platform.secretFiles`
   keyed by the same names, and set `config.secrets` to
   `{source: file, root: <absolute directory>}`. The chart now refuses
   `config.secrets.source: env` and a `secretFiles` with any other source. The
   pod's `fsGroup` reads the files (0440), so the service needs no change to its
   user.
5. **In the service's tests**, call `conformance.NoEnvSecretFields` on each
   version of the document from v2 on, `conformance.SecretsAreFiles` on the
   render, and update `EnvIsDeclared` calls (no `secrets` argument).
6. **Regenerate** goldens and the chart's `values.schema.json` (`just golden`,
   `just chart-schemas`).

## Rollout order

The binary and the file move together here, because a v1.44 binary does not
read `…Secret`. For a service that reads versions (config.md rule 7), ship the
binary that reads both spellings first, then the file, then drop the old
spelling at the next document version; a rollback is the file first, then the
binary.

## Not covered by this release

The Pkl contracts (`examples/url-shortener/contract`) are generated from the
pinned `pkl-contracts` package, which still models `passwordEnv`,
`credentialsEnv` and `platform.secrets`; their shadow output is unchanged until
that package moves. The Python, TypeScript and Kotlin loaders keep their
`secret(name)` helper, which reads the `env` source only.
